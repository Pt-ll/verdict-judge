# Verdict 插件使用说明

Verdict 把 OI / ICPC 风格的**本地评测**做进 VS Code：出题、造数据、评测、调试、重测、
榜单、导出成绩单，全在编辑器里完成。

**完全离线 · 零运行时依赖 · Windows / macOS / Linux 行为一致。**

它不捆绑编译器，只调用你机器上已经装好的 `g++` / `clang++` / `cl`；不联网、不上报，
没有任何 API key 或账号。

---

## 1. 安装

| 来源 | 怎么做 |
| --- | --- |
| Open VSX（VSCodium / Gitpod / Theia） | 扩展面板里搜 `Verdict` |
| 手动装 VSIX | 下载 VSIX → `code --install-extension <文件>` |
| 本仓库开发版 | `pnpm package` 之后装 `dist/verdict-judge-<版本>.vsix` |

装完活动栏（最左侧竖条）会出现 **Verdict** 图标，点开就是评测面板。看不到图标时在活动栏
空白处右键，确认 `Verdict` 是勾上的（VS Code 会把「哪些视图被隐藏」按工作区记下来）。

---

## 2. 三十秒上手

1. 活动栏点 **Verdict** 图标 → 面板顶部是当前比赛与题目，下面三个页签：**题目 / 测试点 / 榜单**。
2. 打开一道题的选手源码（`.cpp` / `.py`），点顶部的 **▶ 评测**，或「测试点」页签里某个点的 `▶`。
3. 判定进状态栏与输出通道；WA 时自动打开「实际输出 ↔ 标准答案」原生 diff，光标停在首个不同的行。
4. 打开 **Testing 面板**（左侧烧瓶图标）→ `题目 > 子任务 > 测试点`，每项都能单独跑、单独调试。
5. 「榜单」页签点 **评测全部** → 选手 × 题目整场跑完，下方出现分数矩阵。
6. 点 **导出 HTML…** → 得到一份断网可开的成绩单，里面有题目与测试点清单，
   点分数格子还能展开逐子任务、逐测试点结果。

## 3. 工作区长什么样

```text
你的工作区/
├── .verdict/
│   ├── contests/                 # 每场比赛一个文件（可以放好几场）
│   │   ├── internal-2026.json    # 题目列表、选手、重测上限
│   │   └── practice-01.json
│   ├── data/                     # 测试数据总库：一个题目一个文件夹
│   │   ├── A/                    # 1.in / 1.out / 2.in / 2.out ...
│   │   └── B/
│   ├── submissions/              # 评测记录（运行产物，不入库）
│   │   └── internal-2026.json
│   └── problems/
│       ├── A/
│       │   ├── problem.json      # 题目：限制、比较方式、测试点、子任务
│       │   └── extra/            # checker.cpp / interactor.cpp / std.cpp / testlib.h
│       └── B/
└── players/                      # 选手源码，放进去就自动算一名选手
    ├── alice/A.cpp
    └── bob/A.cpp
```

三条约定值得记住：

1. **数据集中在总库** `.verdict/data/<题目 id>/`，用文件夹名区分题目。面板「测试点」页签上
   直接写着当前题目的数据目录，点「打开数据目录」就跳过去。
2. **题目库是全局的**，比赛只记题目 id 列表 —— 所以同一道题可以同时出现在多场比赛里，
   各场的成绩、重测次数互不影响。
3. **`players/<名字>/<题目>.cpp` 放进去就是一名选手**，不用去改比赛配置；
   显式写进配置的选手优先（可以自定义显示名与目录）。

### 兼容 0.1.2 及更早的布局

老工作区**不用搬家**，下面两种写法都照读：

| 旧写法 | 现在怎么处理 |
| --- | --- |
| `.verdict/contest.json`（单场比赛） | 当成一场比赛读，`contests/` 下的新比赛可以与它共存 |
| `.verdict/submissions.json` | 同上，作为那场比赛的记录文件 |
| 题目包内的 `data/`（`.verdict/problems/A/data/`） | 存在就用它，总库里的同名目录不会被误用 |
| 测试点路径写成 `"data/1.in"`（相对题目包根目录） | 加载时归一成 `"1.in"`（相对数据目录），指向的文件不变 |

数据想放别处也行：`problem.json` 里写 `"dataDir": "../../shared/A"`（相对题目包根目录）。
既不是包内 `data/` 也不是总库约定位置时，这个字段才会被写回文件。

## 4. 侧边栏面板

顶部一行：当前题目、比赛、当前源码，以及 `▶ 评测` / `🐞 调试` / `■ 取消`。
底部一行：进度与最近一次结果。

### 题目页签

- **比赛选择器**：一个工作区可以放好几场，切换后题目、测试点、榜单全跟着换；旁边的 `＋` 再开一场。
- **题目列表**：`★` 表示在当前比赛里；`＋` 把题目加进当前比赛，`−` 移出（题目包与数据都保留）；
  `🗑` 删除题目，确认框给三个选择——
  **只从比赛移除** / **删除题目包（保留数据）** / **连数据一起删除**。
  删除走系统回收站，删错能捞回来；题目若出现在别的比赛里，会先从那些比赛里摘干净。
- **新建 / 导入 / 导出 / 删除题目包**。
- **限制**：时间、内存、栈上限、输出上限，改完直接写回 `problem.json`。
- **比较方式**：五种模式任选，`real` 的误差、`spj` / `interactive` 的文件用文件选择器指定。

### 测试点页签

- 按子任务分组，每行给最近一次判定、用时、内存：
  `▶` 只跑这一个点、`🐞` 用它起调试、`⇄` 打开 diff、`▸` 展开看**输入 / 标准答案 / 实际输出**。
- 展开后能改归属、把测试点移出登记（**只取消登记，`data/` 里的文件不动**）、直接打开输入或答案文件。
- 子任务可增删、改分值 / 依赖 / 计分方式（`min` 组内全对 / `sum` 按点求和），也能「按点均分」。
- **扫描新测试点**：把数据目录里还没登记进 `problem.json` 的 `*.in` / `*.out` 补进来。

### 榜单页签

- 选手 × 题目矩阵，点单元格看这一格的重测详情并重测（受重测上限约束）。
- **评测全部**、**导出 HTML…**、**完整榜单**（编辑器里的大表格 + 统计）。

> 面板只是 `problem.json` / `contests/*.json` 的一个视图：每次编辑都是读-改-写，
> 与手改文件完全等价。文件在编辑器外面被改（手改、git 切分支）时面板会跟着刷新，
> 不会出现两份数据。

## 5. 出题流程

1. **新建比赛**：面板比赛选择器旁的 `＋`，或命令 `Verdict: 新建比赛`。
   填比赛 id、标题、重测上限、选手（留空也行，`players/` 会自动发现）。
2. **新建题目**：`Verdict: 新建题目`，填题目 id、时限、内存。
   数据目录会自动建在 `.verdict/data/<题目 id>/`。
3. **放数据**：`1.in` / `1.out`、`2.in` / `2.out` … 可以放很多组；
   答案后缀支持 `.out` / `.ans` / `.expected`。
4. **扫描测试点**：面板「测试点」页签 → **扫描新测试点**，或命令 `Verdict: 导入测试点`。
5. **分子任务**：`＋ 子任务`、`按点均分`，或 `Verdict: 配置子任务` 打开文件细调。
6. **设比较方式**：默认（忽略行尾空白）/ 逐行 / 实数（绝对+相对误差）/ testlib SPJ / 交互题。
7. **办比赛**：选手源码放进 `players/<选手>/<题目>.cpp`，「榜单」页签点 **评测全部**。

### problem.json 最小示例

```jsonc
{
  "id": "A",
  "name": "A. 求和",
  "limits": { "timeMs": 1000, "memoryMb": 256, "stackMb": 256, "outputKb": 4096 },
  "comparator": { "mode": "default" },
  "subtasks": [
    { "id": "1", "name": "小数据", "points": 30, "tests": ["1"], "dependsOn": [], "scoring": "min" },
    { "id": "2", "name": "大数据", "points": 70, "tests": ["2"], "dependsOn": ["1"], "scoring": "min" }
  ],
  "tests": [
    { "id": "1", "input": "1.in", "answer": "1.out", "points": 30, "subtask": "1" },
    { "id": "2", "input": "2.in", "answer": "2.out", "points": 70, "subtask": "2" }
  ]
}
```

- `tests` 可以整个不写（或写 `[]`）：会自动扫描数据目录。
- 测试点路径相对**数据目录**（所以通常就是 `1.in`）。
- 子任务成员关系以 `subtasks[].tests` 为准；只有它为空时才用测试点的 `subtask` 字段补。
  两边说法不一致会直接报错，不会悄悄按其中一个算分。
- 子任务依赖没满分时，后继子任务记为 **跳过（0 分）**，而不是「跑了但没得分」。
- 非法数值、引用不存在的测试点 / 子任务、依赖成环、重复 id、空子任务都会在加载时报错，
  而且一次列全部问题。

### contest.json 最小示例

```jsonc
{
  "id": "internal-2026",
  "title": "内部训练赛 #3",
  "maxRejudge": 3,
  "problems": ["A", "B", "C"],
  "contestants": [
    { "id": "alice", "name": "Alice", "folder": "players/alice" }
  ]
}
```

`problems` 与 `contestants` 都能不写：前者允许是空数组（刚建出来的比赛就是这样），
后者留空则由 `players/` 自动发现。文件名（去掉 `.json`）就是比赛 id，与里面的 `id`
必须一致。

## 6. 评测、判定与调试

### 判定

| 判定 | 含义 |
| --- | --- |
| `AC` | 通过 |
| `WA` | 输出与标准答案不同（首个不同行会告诉你差在哪） |
| `PC` | 表现错误（SPJ 的 PE：答案对但格式不规范） |
| `TLE` | 超过时间限制 |
| `MLE` | 超过内存限制 |
| `OLE` | 输出超过上限 |
| `RE` | 运行时错误（非零退出码或异常信号） |
| `CE` | 编译失败，诊断进问题面板并可点击跳转行列 |
| `UKE` | 无法判定（例如 checker 编译失败、比较方式不认识）——如实上报，不假装判过 |

### 触发评测的四种方式

- 源码顶部的 CodeLens `▶ 评测` / `🐞 调试首测点` / `⚙ 限制`
- 面板顶部 `▶ 评测`（整题）或测试点行上的 `▶`（单点）
- Testing 面板里对某个题目 / 子任务 / 测试点点运行
- 命令 `Verdict: 评测当前文件`

只跑了部分测试点时，面板不会显示总分——那是个**下界**，子任务计分是拿整套数据算的，
把单点结果当结论展示是在骗人。要完整分数点「评测整题」。

### 调试

- 用当前题目的第一个测试点（或你点的那一个）起调试会话，**测试点输入自动接到 stdin**，
  不需要手动喂。
- 断点、单步、变量查看都由你已装的调试扩展负责：C++ 是 `ms-vscode.cpptools`（macOS/Linux
  底层是 lldb / gdb），Python 是 `ms-python.debugpy`。没装时会给一条可操作提示 + 搜索按钮。
- **交互题**用「录制-重放」：先真实跑一局录下交互器发过来的提示串，再用它当调试时的 stdin，
  于是也能在真实输入下断点单步。
- 设置 `verdict.debugStopAtEntry: true` 可以让会话先停在程序入口。

### 对比输出

WA / PC 时自动打开原生 diff 并跳到首个不同的行；也可以点测试点行上的 `⇄`，
或命令 `Verdict: 对比输出` 挑一个测试点。

## 7. 比赛：多场、重测、榜单、成绩单

- **多场比赛**：`.verdict/contests/<id>.json`，一场一个文件。面板上切换，
  命令 `Verdict: 切换比赛` 也能切。当前用的是哪一场会记在工作区状态里。
- **题目重叠**：题目库是全局的，比赛只记 id 列表。同一道题可以进好几场比赛，
  数据也只有一份。用题目行上的 `＋` / `−`（或对应命令）加减比赛里的题。
- **评测全部**：选手 × 题目逐个跑，每跑完一条就落盘，中途取消不丢已完成的。
  找不到源码的格子会列出「跳过（没有源码）」，这不是错误。
- **重测**：点榜单里的格子，或命令 `Verdict: 重测`。每个格子有重测次数上限
  （`maxRejudge`），到顶后拒绝并说明原因。「评测全部」是整场重跑，不受这个上限约束。
- **榜单**：OI 赛制取每格最高分（同分取更早的那次），并列名次跳号（1、2、2、4）。
- **导出 HTML 成绩单**：自包含、断网双击可开，不含任何外部资源。里面有两部分：
  **题目与测试点**清单（每道题的限制、比较方式、子任务表、逐测试点表），
  以及可点开的**提交详情**（子任务得分、逐测试点判定 / 得分 / 用时 / 内存 / 首个不同行）。

> 成绩单里不含实际输出的正文：评测记录只存判定、分数、耗时、内存，
> 输出上限按 KB 算，塞进成绩单会让文件大到没法发。要看输出请用 diff 或重跑一次。

## 8. 题目包的导入导出

- **导出**：`Verdict: 导出题目包` → 生成一个 ZIP，含 `problem.json`、`extra/` 与全部测试数据
  （数据在总库里也会被收进去），每次导出字节完全一致，便于比对与入库。
- **导入**：`Verdict: 导入题目包` → 解到 `.verdict/problems/<题目 id>/`，
  包里的 `data/` 自动搬进总库 `.verdict/data/<题目 id>/`，并顺手加进当前比赛。
  目标目录已存在时会拒绝覆盖（不会静默盖掉别人正在改的数据）。

## 10. 设置

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `verdict.compiler` | 空 | 编译器完整路径；留空自动探测 `g++` → `clang++` → `cl` |
| `verdict.flags` | `["-O2","-std=c++17"]` | 编译参数 |
| `verdict.defaultTimeMs` | `1000` | 默认时间限制（毫秒） |
| `verdict.defaultMemoryMb` | `256` | 默认内存限制（MB），同时作为栈上限 |
| `verdict.outputLimitKb` | `4096` | 输出上限（KB），超过判 OLE |
| `verdict.comparator` | `default` | 没有题目包时的比较方式（`default` / `line` / `real`） |
| `verdict.realAbsEps` / `realRelEps` | `1e-6` | 实数比较的绝对 / 相对误差 |
| `verdict.testlibPath` | 空 | `testlib.h` 所在目录或文件 |
| `verdict.autoDiff` | `true` | WA / PC 时自动打开 diff |
| `verdict.debugStopAtEntry` | `false` | 调试时先停在程序入口 |
| `verdict.debug` | `false` | 在输出通道打印调试日志 |

题目包里的限制与比较方式优先于这些默认值。

`testlib.h` **不随扩展提供**（扩展零依赖、不联网）。查找顺序是：
题目包 `extra/` → 工作区 `.verdict/testlib/` → 设置 `verdict.testlibPath`。
都没找到时会给出可操作提示；checker 编译失败记为该测试点 `UKE`（不是 `CE`），不会被当成
选手的编译错误。

## 11. 常见问题

**面板显示「还没有比赛」/ 一片空白？**
先确认这个窗口打开的是**文件夹**（工作区），而不是单个文件；再看 `.verdict/contests/` 下
有没有 `*.json`，`players/` 下有没有选手源码。面板顶部有横幅时会写明读不出来的原因，
并给「重新读取」与「打开比赛配置」两个按钮。

**数据到底该放哪？**
面板「测试点」页签上写着当前题目的数据目录（`.verdict/data/<题目 id>/`）；
命令 `Verdict: 导入测试点` 的提示里也会写。老工作区的 `.verdict/problems/<id>/data/` 依然有效。

**为什么单点运行后不显示总分？**
因为那是下界：子任务计分是整套数据算出来的，只跑一个点时依赖它的子任务会变成 0 分。
面板此时只说「点『评测整题』看完整得分」。

**WA 了但我看不到程序输出了什么？**
评测时的输出在内存里，WA 会自动开 diff；重开编辑器之后只有判定与统计（成绩单同理）。
想看某一次的完整输出，重跑那个测试点即可。

**删题目会删掉数据吗？**
三个选项由你选：只从比赛移除 / 删题目包保留数据 / 连数据一起删。都走系统回收站。
如果同一道题还在别的比赛里，会先从那些比赛里摘掉（否则那些比赛下次加载会直接报错）。

**3 平台上行为一致吗？**
评测链路在 Windows / macOS / Linux 的 CI 上都跑集成测试：编译、运行、时限、内存、
输出截断、进程树清理都分平台实现（POSIX 杀进程组，Windows 用 `taskkill /T /F`）。

**改了代码怎么本地看效果（仓库开发）？**
在仓库窗口按 `F5`（调试配置 `运行扩展（testdata 工作区）` 会直接以样例工作区启动）；
改完 `src/**` 在扩展开发宿主窗口按 `Cmd+R` 重载，改了 `package.json` 的贡献点必须重载。

## 12. 已知限制

- **Linux 上的调试输入注入未验证**：macOS（lldb）已用集成测试证明可用；
  gdb 走 `set inferior-tty`，真没生效时会退化成手动喂输入。
- **MSVC 调试器没有注入能力**，调试时只能手动输入（提示里会给出输入文件路径）。
- **Python 调试（debugpy）只有配置层面的单测**，没有真机验证。
- **交互题调试是录制-重放**：程序这次的反应若与录制时不同（自适应交互器），后面会对不上。
- **并行评测与「保存即评测」还没实现**，整场比赛是逐个提交顺序跑的。
- **`limits.procCount` 没有实现**：写了会明确报错，不会静默忽略。
- **成绩单不含实际输出正文**（原因见 §7 末尾）。
- 提交答案题（output-only）与通信题是后续计划，本版没有。
- 数据文件上的「📋 关联测试点」CodeLens 还没做（源码上的三个按钮已经可用）。
